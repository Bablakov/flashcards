## Зачем именно так

- **Файл на объект** — добавление карточек на ПК и телефоне без синхронизации создаёт
  разные файлы, git сливает их без конфликта. Это прямой ответ на требование «чтобы
  ничего не ломалось при добавлении с двух устройств».
- **Журнал вместо поля прогресса** — каждое устройство пишет только в свой файл,
  поэтому конфликт по прогрессу невозможен в принципе, а не «разрешается драйвером».
  Бонусом из журнала бесплатно получается недельный отчёт и серия дней.
- **Медиа по хешу** — два устройства физически не могут создать разные файлы с одним
  именем, бинарные конфликты исчезают как класс.
- **Мягкое удаление** — «удалено там / изменено тут» единственный конфликт, который git
  не решает сам, поэтому мы его не создаём.

## Что всплыло по дороге

**Два окна на одних данных затирают друг друга.** Хранилище держит дерево файлов в памяти
вкладки и сбрасывает на диск с задержкой. При двух открытых вкладках карточка, созданная
в одной, исчезла после записи из второй. Для ПК-приложения это означает обязательный
single-instance lock (внесено в спецификацию, §10), для веба — не открывать в двух вкладках.
