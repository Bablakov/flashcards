# Выпуск 1.0.0 → 1.0.11: что ломалось на живых устройствах и почему

> Сессия 2026-08-18/19, продолжение [`2026-08-18-phases-2-8.md`](./2026-08-18-phases-2-8.md).
> Итог: приложение работает на ПК и на телефоне, синхронизация через
> `flashcards-data` идёт в обе стороны, обновления приходят сами.

## Что сделано

Двенадцать версий за один заход. Ниже — только то, что оказалось неочевидным.

| Версия | Симптом у пользователя | Настоящая причина |
|---|---|---|
| 1.0.1 | «HTTP Error: 403 Forbidden» на ПК | У токена стояло `Contents: Read-only`. Проверено запросом к обоим git-эндпоинтам с заведомо рабочим токеном: репозиторий и схема авторизации были в порядке |
| 1.0.2 | На телефоне синхронизация зависала на `pull`, интерфейс переставал реагировать | Глобальный патч `fetch` от Capacitor: нативный слой принимает только строку или JSON, а git гоняет двоичные пакеты. Патч ещё и перехватывал все запросы приложения — отсюда «ломается всё после любой кнопки» |
| 1.0.3 | Установщика не было на странице релиза, автообновление ПК не работало | `electron-builder` создавал **свой черновик** релиза с тем же тегом: APK лежал в опубликованном, `.exe` и `latest.yml` — в черновике |
| 1.0.4 | — | Имя установщика с пробелами: GitHub меняет их на точки, а `latest.yml` ссылается на вариант с дефисами |
| 1.0.5 | «Failed to execute 'atob'» при клонировании | Нативный HTTP отдаёт двоичный ответ в base64, а текстовый — обычной строкой. Код декодировал как base64 всё подряд |
| 1.0.6 | «Your local changes would be overwritten by checkout: meta.json» | На телефоне уже лежали демо-карточки, поверх которых git отказывается разворачивать репозиторий |
| 1.0.7 | «Карточка не найдена» сразу после создания | Дерево каталогов в хранилище пишется с задержкой; переход в редактор перезагружает страницу раньше |
| 1.0.9, 1.0.10 | «Could not find `<хеш>`» при коммите после карточки с картинкой | То же самое, но терялись служебные объекты git |
| **1.0.11** | те же два симптома возвращались | **Причина всех «потерь»: мой собственный сброс на диск вызывался у несуществующего объекта и молча превращался в паузу** |

## Главный урок: 1.0.11

Начиная с 1.0.7 приложение «принудительно сбрасывало дерево файлов на диск»
после каждой записи. Метод вызывался у `getFS()._backend`, но такого свойства
у файловой системы нет — `_backend` лежит внутри `promises`. Условие тихо
не выполнялось, и каждый «сброс» был обычным ожиданием в 600 мс.

Проверено измерением в браузере (отладочный доступ `exposeFsDebug`, только
в режиме разработки): **40 файлов по 100 КБ пачкой, сразу перезагрузка**.

- без сброса — не выживает **ничего**, пропадает даже сам каталог;
- со сбросом (`fs.promises.flush()`) — выживают **все 40**.

Механика: библиотека откладывает запись дерева на 500 мс и **сбрасывает таймер
при каждой следующей записи**. Одиночная правка успевала сохраниться, а серия —
нет вообще. Карточка с картинкой — это как раз серия: файл карточки, файл
картинки и несколько объектов git. Отсюда и то, что правка текста проходила
спокойно, а добавление картинки ломало синхронизацию.

Теперь при отсутствии метода приложение не деградирует молча, а пишет
предупреждение в консоль.

## Что заодно появилось из-за этих поломок

- **«Проверить доступ»** — отдельно спрашивает GitHub про чтение и запись,
  поэтому «нет права записи» больше не выглядит как «403 Forbidden».
- **Ошибки называют этап** — подключение, коммит, получение изменений, отправка.
- **Блок «О приложении»** — версия, платформа, время последней синхронизации,
  идентификатор устройства и кнопка «Скопировать диагностику».
- **Самовосстановление**: если объект всё же потерян, `.git` пересобирается из
  удалённого репозитория, а рабочие файлы остаются и уходят первым коммитом.
  Осталось второй линией обороны.
- **Обновление одним диалогом** на Android: скачивание с процентами и передача
  файла системному установщику.
- **Индикатор синхронизации** и погашенные кнопки, в том числе при автоматической.
