# Сборка для iPhone

> Сессия 2026-10-06, выпуск **1.1.4**. Запрос: «нужно создать сборку под iOS
> с тем же функционалом, что в последней версии для Android» (1.1.3).

## Исходная ситуация

- Приложение — Next.js (статический экспорт) внутри Capacitor 7. Весь
  интерфейс и логика — общий веб-код, нативного кода своего нет. Значит,
  функции Android переезжают на iOS сами; работы — в сборке и в местах, где
  код различает платформы.
- Папка `android/` в репозитории не хранится — её создаёт CI из шаблона
  Capacitor и дописывает нужное шагами workflow. iOS сделан так же.
- **iOS нельзя собрать на Windows**: нужен Xcode, а он есть только на macOS.
  Поэтому сборка — только в GitHub Actions на macOS-раннере. Для публичного
  репозитория эти минуты бесплатны.

## Что сделано

### 1. Workflow `ios.yml`

Повторяет `android.yml` шаг в шаг: `npm ci` → проверки модели → `next build`
→ `npx cap add ios` → `cap sync` → иконки → права → версия → сборка → релиз.

| Шаг | Зачем |
|---|---|
| `runs-on: macos-15` | Xcode 16 — минимум для Capacitor 7 |
| Иконки из `ios-assets/logo.png` | У `assets/icon.png` прозрачные скруглённые углы. `@capacitor/assets` заливает прозрачность белым (по умолчанию `#ffffff`), и на iPhone вокруг значка были бы белые уголки. Значок отдаётся как «логотип» с фоном `#1a1a1a` — цветом самой иконки, заставка — фоном тёмной темы `#171717` |
| `NSCameraUsageDescription`, `NSPhotoLibrary*UsageDescription` | Без них iOS **аварийно закрывает** приложение при первом обращении к камере или галерее — это аналог шага с разрешением на Android |
| `ITSAppUsesNonExemptEncryption = NO` | Не нужно для установки, но избавит от вопроса про шифрование, если когда-нибудь дойдёт до TestFlight |
| `MARKETING_VERSION` / `CURRENT_PROJECT_VERSION` в `project.pbxproj` | Версия как у APK, номер сборки = номер запуска workflow (как `versionCode`) |
| `xcodebuild … CODE_SIGNING_ALLOWED=NO` | Сборка без подписи — см. ниже |
| `Payload/App.app` → zip → `.ipa` | Это и есть формат `.ipa` |
| На тег — `gh release upload` | Тот же приём, что у ПК-сборки: ждём, пока Android создаст релиз, и докладываем файл |

### 2. Почему `.ipa` без подписи

Варианты, которые были:

1. **Платный Apple Developer ($99/год)** → подпись на год, TestFlight,
   обновления «по кнопке». Нужны аккаунт, сертификат и профиль — их нет,
   а завести их может только владелец аккаунта.
2. **Неподписанный `.ipa` + Sideloadly/AltStore** (выбрано). Программа на ПК
   сама подписывает файл бесплатным Apple ID при установке. Цена — подпись
   живёт 7 дней, не больше трёх таких приложений.
3. **Сайт (PWA) в Safari** — отпадает: синхронизации нужен нативный HTTP
   (в браузере CORS, а прокси отменён), локальные уведомления в PWA на iOS
   работают плохо, а данные Safari может стереть через 7 дней без посещений.

Вариант 2 — единственный, который работает прямо сейчас без денег и без
действий в чужих аккаунтах. Переход на вариант 1 потом — это только шаг
подписи в workflow, код приложения менять не придётся.

### 3. Код: где платформы различаются

| Файл | Изменение | Почему |
|---|---|---|
| `lib/platform.ts` (новый) | `detectPlatform()` → `desktop / android / ios / web` | Раньше любая нативная платформа считалась Android |
| `lib/updates.ts` | На iOS — открыть страницу релиза; обновление предлагается, только если в релизе есть `.ipa` | Приложение на iOS не может установить другое приложение, а скачивание APK там бессмысленно. Сборка iOS самая долгая и докладывает `.ipa` последней — без проверки iPhone увидел бы «доступна версия» раньше, чем появился файл |
| `components/UpdateBanner.tsx` | Текст и кнопка «Открыть релиз» для iPhone | Объясняет, что ставить надо с компьютера тем же Apple ID |
| `components/AboutBlock.tsx` | Платформа «iOS» в диагностике | Чтобы скопированная диагностика не врала |
| `components/NativeBridge.tsx` | Кнопка «Назад» — только Android; на iOS цвет строки состояния следует теме (`@capacitor/status-bar`) | На iPhone страница рисуется под часами. При тёмной теме на светлой системе часы были бы тёмными на тёмном фоне |
| `components/TopBar.tsx` | Отступ сверху `env(safe-area-inset-top)` | `viewport-fit=cover` уже стоял, но отступа сверху не было — заголовок и кнопки уехали бы под «чёлку» / Dynamic Island |
| `app/globals.css` (`.modal-backdrop`), `components/Toaster.tsx` | Отступ снизу `env(safe-area-inset-bottom)` | Нижние листы и уведомления ложились на полосу «домой». Нижние панели это уже учитывали |
| `capacitor.config.ts` | `ios.backgroundColor = #171717` | Белая вспышка между заставкой и первой отрисовкой |

Отступы общие для всех платформ: где система их не сообщает (ПК), они нулевые.

### 4. Что проверено в исходниках Capacitor iOS, а не предположено

- **Синхронизация git.** `lib/git-http.ts` шлёт тело base64 с
  `dataType: "file"` и просит ответ `arraybuffer`. В iOS-версии плагина
  (`CapacitorUrlRequest.getRequestData`) `file` декодируется из base64,
  а ответ (`HttpRequestHandler.buildResponse`) отдаётся base64 для
  `arraybuffer` — JSON-разбор включается только при `Content-Type:
  application/json`, у ответов git он другой. Плагин HTTP регистрируется
  всегда, независимо от `CapacitorHttp.enabled: false`.
- **Ссылки наружу.** `window.open` на iOS Capacitor передаёт в Safari
  (`createWebViewWith` → `UIApplication.shared.open`).
- **Маршруты.** Пути без расширения iOS-сервер отдаёт как `index.html` —
  так же, как Android, поэтому навигация Next.js ведёт себя одинаково.
- **Уведомления.** Еженедельный повтор `on: { weekday, hour, minute }`
  поддерживается и на iOS; лимит iOS в 64 запланированных уведомления
  не мешает — их максимум семь.

### 5. Как проверена сборка

Первый же запуск `ios.yml` прошёл (run 37394388873, сам `xcodebuild` —
около полутора минут). Скачанный `.ipa` разобран вручную:

- bundle id `com.kirill.flashcards`, имя «Flashcards», минимальная iOS 14.0,
  версия и номер сборки подставились;
- в `Frameworks/` все шесть плагинов (app, camera, filesystem,
  local-notifications, status-bar, file-opener) плюс Capacitor и Cordova;
- в `public/` весь статический экспорт: 9 экранов, 58 чанков JS, стили;
- описания доступа к камере и фото — в `Info.plist`, по-русски;
- значок и заставка созданы (`AppIcon-512@2x.png`, `Splash.imageset`).

### 6. Попутно: сломанная сборка Android

В тот же день перестала собираться любая версия APK — даже без изменений
в коде. На раннерах GitHub обновились Android cmdline-tools до 16.0, а
`android-actions/setup-android@v3` по умолчанию ставит пакеты
`tools platform-tools`; пакета `tools` в новой версии нет, `sdkmanager`
завершался с ошибкой. В `android.yml` пакеты заданы явно —
`packages: "platform-tools"`. Первый тег `v1.1.4` из-за этого пришлось
поставить заново на коммит с починкой.

## Что ещё нужно сделать

1. **Первый запуск на живом iPhone** — сборка проверена только компиляцией.
   Что проверить по порядку:
   - верхняя панель не под часами, нижняя — не на полосе «домой»;
   - «Клонировать» и синхронизация (главный риск — нативный HTTP);
   - камера и выбор из галереи (запрос разрешения на русском);
   - напоминание: «Проверить через 15 секунд» и свернуть приложение;
   - смена темы меняет цвет часов.
2. **Продление подписи раз в 7 дней** — неудобство бесплатного Apple ID.
   Если станет мешать: платный аккаунт разработчика и шаг подписи в
   `ios.yml` (секреты: сертификат `.p12`, пароль, профиль, Team ID), дальше
   можно и TestFlight. Альтернатива без денег — SideStore/AltStore, они
   продлевают подпись с самого телефона.
3. **Свайп «назад» от края экрана** на iOS не работает — назад ведёт стрелка
   в верхней панели. Включается только нативной правкой
   (`allowsBackForwardNavigationGestures`), в Capacitor 7 для этого нет
   настройки.
4. **Синхронизация при сворачивании.** iOS приостанавливает приложение через
   несколько секунд после ухода в фон; отправка коммитов «при выходе» может
   не успеть. Коммиты не теряются — уедут при следующем запуске, — но если
   это будет заметно, нужен фоновой таск (`@capawesome/capacitor-background-task`
   или аналог).
5. **Ключ подписи Android** в `Desktop\flashcards-keystore\` больше не лежит
   (поиск по рабочему столу, документам, загрузкам и облачным папкам ничего
   не нашёл). Сборки это не ломает — ключ лежит в секретах GitHub, — но
   прочитать его оттуда нельзя. Стоит убедиться, что копия ключа и пароля
   где-то сохранена: без неё при потере секретов APK больше не обновить
   поверх установленного.
