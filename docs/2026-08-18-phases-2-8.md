## Ключевые решения и почему так

**Иерархия хранится через `parentId`, а не вложенными папками.** Настоящие папки означали
бы, что перенос группы — это массовое переименование файлов, а такое при работе с двух
устройств гарантированно конфликтует. С `parentId` перенос ветки меняет один файл.
Циклы («перенести группу внутрь своего потомка») отсекаются проверкой перед записью.

**FSRS вместо фиксированных интервалов.** Корзины Лейтнера гоняют лёгкие и трудные
карточки с одинаковой частотой, а SM-2 после серии ошибок навсегда оставляет карточку
в частых повторах. FSRS оценивает стабильность памяти по каждой карточке; уровни 1–5
остались, но теперь это отображение стабильности, а не место хранения.

**Ответы копятся пачкой, всё остальное коммитится сразу.** Требование «создал карточку —
сразу коммит» выполнено буквально, но сотня коммитов за сессию превратила бы историю
в мусор, а конфликтов в журнале нет по устройству формата — значит поштучные коммиты
там ничего не защищают.

**Git из главного процесса Electron.** Это решает CORS без стороннего прокси: запрос идёт
мимо браузерной песочницы, токен не покидает устройство. Тот же приём на Android —
нативный HTTP. Прокси остаётся нужен только браузерной версии.

**Один экземпляр приложения.** Хранилище держит дерево файлов в памяти окна и пишет на
диск с задержкой: два окна на одних данных затирают правки друг друга (проверено на
практике в фазе 1). В ПК-сборке стоит single-instance lock.

## Проверка

- `npx tsc --noEmit` — чисто; `npm run build` — 9 маршрутов, статический экспорт;
- `npm run test:model` — 47 проверок: FSRS (рост и падение стабильности, лимит уровня,
  влияние удерживаемости), сборка сессии (режимы, фильтры, лимиты, порядок), слияние
  файлов, дерево групп, отчёт;
- живая проверка в браузере: главная с подсказкой первого запуска и плитками групп,
  отчёт (серия, неделя, уровни, прогноз, разрез по группам), экран настройки
  самопроверки и сама сессия в режиме «Тренировка» с пометкой «без записи прогресса»;
- ПК-сборка: `npx electron .` запускается, внутренний сервер отдаёт страницы (200).

## Что осталось за пределами этой сессии

1. **Прогон на реальном телефоне.** APK собирается в CI, но нативные ветки (уведомления
   Android 13/14, нативный HTTP для git, установка обновления поверх) можно проверить
   только на устройстве.
2. **Keystore.** Нужно один раз сгенерировать ключ, положить его в GitHub Secrets
   (`ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`,
   `ANDROID_KEY_PASSWORD`) и в личный бэкап. Потеря ключа = невозможность обновлять
   приложение поверх.
3. **Публичность репозитория кода.** Решение принято, но переключить видимость
   на GitHub нужно вручную — без этого автообновление не увидит релизы.
4. **Иконки приложения.** Сейчас есть только SVG; для установщика и APK нужны PNG/ICO
   (`@capacitor/assets` и поле `build.win.icon`).
5. **Переобучение параметров FSRS** под свою историю — журнал для этого есть, оптимизатор
   отложен на 1.1.
