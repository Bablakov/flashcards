# Сайт вместо установки (GitHub Pages)

> Сессия 2026-10-06, выпуск **1.1.5**. Запрос: «нужен другой способ пользоваться
> приложением… как веб-приложение, открывать с GitHub… не хочу устанавливать
> через Sideloadly… чтобы само синхронизировалось». Отдельно: «самое главное —
> не убить реализацию для ПК и Андроида».

## Исходная ситуация

- На iPhone приложение ставилось только через Sideloadly с компьютера, и подпись
  жила 7 дней. Пользователю это неудобно.
- Веб-сборка (статический экспорт Next.js) была всегда, но синхронизация в ней
  не работала: git-сервер github.com не отдаёт CORS-заголовки, и браузер режет
  запросы. Раньше это решалось своим CORS-прокси на Cloudflare — решение
  отменено ещё в августе, когда ПК и телефон ушли на нативный HTTP.
- Повторно поднимать прокси значило бы: аккаунт на Cloudflare, токен через
  посредника, ещё одна точка отказа.

## Решение: git поверх GitHub API

`api.github.com` CORS **отдаёт**. Новый модуль `lib/github-api-transport.ts`
подключается к isomorphic-git как HTTP-клиент и изображает git-сервер: принимает
те же запросы протокола smart HTTP и отвечает теми же байтами, а данные берёт и
пишет через REST и GraphQL API. Весь остальной код синхронизации — clone, pull
с merge-драйвером, push, счётчик несинхронизированного — не изменился и не знает,
что сервер ненастоящий.

| Запрос git | Что делает транспорт |
|---|---|
| `info/refs` (чтение) | ветки из `git/matching-refs/heads`, HEAD из `repos/{repo}` |
| `info/refs` (запись) | то же + проверка права записи: создание пустого файла (идемпотентно, следа не оставляет) |
| `git-upload-pack` | коммиты от запрошенного вниз до тех, что уже есть на устройстве (GraphQL `history`), папки (`git/trees?recursive=1`), файлы (`git/blobs`, 6 параллельно) → packfile |
| `git-receive-pack` | разбор packfile от isomorphic-git → `POST git/blobs`, `git/trees`, `git/commits` в порядке зависимостей → сдвиг ветки `PATCH git/refs` без force |

### Почему это вообще сходится

Git адресует объекты хешем содержимого, поэтому восстанавливать их надо бит в бит:

- **файлы и папки** однозначно собираются из ответа API (порядок записей и режим
  `40000` — как в git);
- **коммит** — из полей GraphQL: только там дата хранит часовой пояс автора
  («+03:00»); REST отдаёт её в UTC, и хеш бы не сошёлся;
- **отправка**: GitHub создаёт коммит из тех же полей (имя, почта, дата с поясом,
  сообщение) и не подписывает его — хеш совпадает с локальным.

Проверено до написания кода, на репозитории данных: **98 из 98** коммитов
собраны точно, пробный коммит через API с поясом +03:00 совпал с локальным хешем
(ветка при этом не двигалась). Каждый объект в транспорте сверяется по хешу;
расхождение — понятная ошибка, ветка на GitHub сдвигается только когда совпали все.

### Как проверено

`npm run test:github` (`scripts/test-github-transport.ts`) — на настоящем
репозитории данных, сверка с настоящим git:

1. clone `--depth 1` через API: HEAD = main на GitHub, 192 файла, рабочая копия
   чистая, `git ls-files` настоящего git даёт столько же (197 запросов, ~20 с);
2. `--write`: push во временную ветку (вложенные папки, кириллица в имени,
   двоичный файл 70 КБ) → настоящий git клонирует, `git fsck --full --strict`
   чист, файл цел;
3. параллельные правки: коммит настоящего git + коммит «сайта» → pull делает
   слияние → push → настоящий git получает тот же merge-коммит, fsck чист;
4. устаревшая ветка: push отклонён, чужой коммит не затёрт;
5. `main` не изменился — тест падает при любой попытке тронуть чужую ветку
   (защита в обёртке `fetch`, а не обещание). Временная ветка удаляется.

Плюс живой прогон собранного сайта в Chrome (локальная имитация GitHub Pages
с подпапкой `/flashcards`, синхронизация во временную ветку):
«Проверить доступ» → «чтение и запись работают»; «Подключить» — 25 с, карточки
и картинки на месте; новая группа → автоматический push → настоящий git: коммит
с поясом +0300, fsck чист; правка «с ПК» → «Синхронизировать» → появилась на
сайте; сервер выключен → главная, группа и настройки открываются из кэша.
После прогона хранилище браузера и временная ветка удалены.

### ПК и Android не тронуты

- Транспорт включается только когда нет ни моста Electron, ни Capacitor — ветки
  ПК (IPC) и телефона (нативный HTTP) стоят раньше и не менялись.
- Подпапка `/flashcards` — только в `build:web`; обычный `npm run build`
  проверен: пути от корня, `sw.js` нет, как раньше.
- `test:model` (53 проверки) и `tsc` проходят.

   только Web Push: нужен сервер-отправитель (вариант без своего сервера —
   расписание в GitHub Actions + ключи VAPID в секретах; cron в Actions
   запаздывает на минуты).
3. **Первая загрузка** — запрос на каждый файл (~200 запросов, ~25 с). Если
   картинок станет на порядок больше — текстовые файлы можно забирать пачками
   через GraphQL.
4. **Лимит GitHub API** — 5000 запросов в час на токен; обычная синхронизация
   тратит 5–20. Ошибка лимита объясняется человеческим текстом.
5. **Сайт на `bablakov.github.io`** делит хранилище браузера с любым другим
   сайтом этого аккаунта на GitHub Pages (одно происхождение). Сейчас других нет.
