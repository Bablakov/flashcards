# Flashcards

Приложение для запоминания по карточкам, где **бэкендом служит ваш собственный
Git-репозиторий**. Ни сервера, ни аккаунтов, ни подписки: карточки, прогресс и
настройки лежат обычными файлами в приватном репозитории на GitHub, а ПК и
телефон — это две его копии.

Работает офлайн полностью: изменения копятся локальными коммитами и уезжают,
когда появится сеть.

## Возможности

- **Группы любой вложенности** — «Здоровье → Анатомия → Кости», карточки могут
  лежать на любом уровне; перенос групп и карточек между ветками.
- **Карточки** с текстом и картинкой на каждой из двух сторон.
- **Интервальное повторение по FSRS** — современная модель памяти вместо
  фиксированных «коробок»: та же удерживаемость достигается за 20–30 % меньше
  повторов. Три кнопки ответа: «вообще не помню / что-то помню / хорошо».
- **Режимы самопроверки**: повторение созревших, только новые, тренировка и
  экзамен (последние два не влияют на прогресс). Область — все группы, выбранные
  или одна с подгруппами; фильтры по уровням, ошибкам, количеству и стороне.
- **Отчёт**: серия дней подряд, лучшая серия, активность за неделю,
  распределение по уровням, прогноз нагрузки на 7 дней вперёд.
- **Локальные напоминания** по расписанию «день недели + время» — без сервера,
  без push-сервисов, работают офлайн.
- **Синхронизация через Git**: коммит на каждое изменение с человекочитаемым
  сообщением, отправка по выбранной политике (при запуске, после изменений,
  при выходе, по расписанию или кнопкой).
- **Импорт и экспорт**: CSV и полный пакет `.fcdeck` вместе с картинками.
- **Автообновление** приложений из релизов GitHub.

## Как устроено хранилище

Репозиторий с данными выглядит так:

```
meta.json                            версия формата данных
settings.json                        настройки (лимиты, расписания)
groups/<id>.json                     группа: имя, обложка, parentId
cards/<id>.json                      карточка: только содержимое
media/<sha256>.webp                  картинки, имя файла = хеш содержимого
journal/<deviceId>/<YYYY-MM>.jsonl   ответы, только дописывание
```

Формат подобран так, чтобы **конфликты при синхронизации были невозможны
структурно**, а не «разрешались» постфактум:

- **один объект — один файл**: добавление карточек на двух устройствах без сети
  создаёт разные файлы, git сливает их без конфликта;
- **удаление мягкое** (`deleted: true`): «удалено там / изменено тут» —
  единственный конфликт, который git не решает сам, поэтому он не создаётся;
- **медиа по хешу содержимого**: два устройства физически не могут создать
  разные файлы с одинаковым именем, бинарных конфликтов не бывает;
- **прогресс — журнал событий, свой файл на каждое устройство**: даже если ПК и
  телефон неделю были офлайн, их истории просто объединятся. Текущее состояние
  карточки вычисляется проигрыванием журнала, а не хранится полем.

Иерархия групп хранится ссылкой `parentId`, а не вложенными папками: перенос
ветки меняет один маленький файл вместо массового переименования, которое
гарантированно конфликтовало бы между устройствами.

Версия формата лежит в `meta.json`. Миграции описаны соседними шагами (1→2, 2→3,
…) и применяются последовательно, поэтому данные любой старой версии доезжают до
текущей. Если репозиторий записан более новой версией приложения, старая
переходит в режим только чтения и не портит незнакомые поля.

## Платформы

| | Как собрано | Сеть для Git |
|---|---|---|
| **Windows** | Electron, установщик NSIS с выбором пути, трей, автозапуск, автообновление | запросы идут из главного процесса — браузерного CORS нет |
| **Android** | Capacitor 7, подписанный APK | нативный HTTP-плагин, тоже мимо CORS |
| **Браузер** | статический экспорт Next.js, PWA | нужен свой CORS-прокси (папка `cors-proxy/`) |

## Установка

Готовые сборки — на странице [Releases](../../releases): `.exe` для Windows и
`.apk` для Android. Как подключить свой репозиторий — пошагово в
[SETUP-USER.md](./SETUP-USER.md); тот же текст показывается в приложении при
первом запуске.

## Разработка

```bash
npm install
npm run dev          # веб-версия на http://localhost:3210
npm run test:model   # 47 проверок: FSRS, сборка сессии, слияние, дерево групп
npm run build        # статический экспорт в out/
npm run desktop      # запустить ПК-версию (Electron)
npm run desktop:dist # собрать установщик в dist-desktop/
npx cap sync android # синхронизировать Android-проект
```

Структура:

```
app/            экраны: главная, группа, карточка, самопроверка, отчёт, настройки
components/     переиспользуемые части интерфейса
lib/
  model.ts      схемы формата данных (zod, все passthrough)
  store.ts      файловое хранилище поверх IndexedDB, дерево групп, медиа, журнал
  progress.ts   FSRS: проигрывание журнала, уровни, прогноз, серии
  session.ts    сборка сессии: режимы, фильтры, лимиты
  repository.ts прикладной слой: группы, карточки, перенос, оценка
  migrate.ts    цепочка миграций формата
  git.ts        clone/pull/push, merge-драйвер
  autosync.ts   коммиты и политика синхронизации
electron/       главный процесс ПК-приложения
scripts/        проверки модели, сид демо-данных
docs/           спецификация и отчёты по этапам работы
```

Сборки собираются в GitHub Actions: `android.yml` (APK) и `desktop.yml`
(установщик Windows). По тегу `v*` публикуется релиз — оттуда приложения и берут
обновления.

## Приватность

- Карточки и прогресс уходят только в **ваш** репозиторий, который вы создаёте сами.
- Personal Access Token хранится локально на устройстве и никогда не попадает
  в репозиторий.
- Проверка обновлений — единственный запрос наружу: публичный GitHub API без токена.
- Аналитики и телеметрии нет.
